# ADR 0027: Owned chat history, retention and short generation writes

- Status: Accepted
- Date: 2026-11-05
- Amends: ADRs 0015 and 0024 for the combined history/controls slice.

## Context

The owner approved durable native history with automatic retention, favourites and unstored drafts. The same-conversation Send guard remains; other chats stay usable. There is one ChatGPT account per Finance user, not a connection-partitioned history product.

Existing conversations already contain native MessageBagNormalizer JSON and a readable projection, including private chart references. The installed Symfony AI BETA1 Agent accepts MessageStoreInterface and saves input, completed tool rounds and final native messages. The reference demo's v0.5 session/cache history is not the installed API and loses native information when flattening replies.

## Decision

Keep conversations and native messages in the central SQLite database. Preserve existing rows, native JSON, initial reference context, signatures, tool relationships and readable projections. Implement the small generation-bound MessageStoreInterface adapter over the existing history column, using native MessageBagNormalizer and ConflictDetector. A fresh owner/conversation/generation-scoped database read and continuation check occur inside the existing BEGIN IMMEDIATE transaction before updating only canonical history. No new serializer, generic transcript engine, AiBundle, message-store table, data converter or provider loop is added. The native Doctrine bridge's configurable table name does not solve its different required row shape (`id`, `version`, `messages`, `updated_at`); adopting that shape would require additional schema/data movement without adding ownership or retention policy.

All chats are automatically retained. New opens an unstored draft; first submitted message creates the conversation. Favourite/Remove favourite maps to the historical physical saved boolean column. No pruning, creation limits or new schema/data conversion is needed. Existing rows, including old empty rows, remain untouched.

Persist the latest generation ID, native ExecutionStatus, captured connection epoch and error, plus per-turn readable status/error. Admission stores the question and its native message before dispatch; broker communication happens after commit. A matching Pending or Running broker delivery claims a fresh attempt UUID in a short immediate transaction. Obsolete and terminal queue messages do not regenerate a reply or write into a later turn. Compare the queued epoch with the freshly read current owner before resolving credentials; cancel stale queued work. Native Agent owns inference, tool execution and message save points. Readable output/chart authorization is committed before publishing private Turbo snapshots; terminal status/error is durable independently of Mercure.

Reuse the existing broker reservation expiry/redelivery and worker `--keepalive=5`; lower the broker-wide reservation from 300 to 90 seconds. This also applies to statement imports served by that broker, not a per-transport execution limit. A failed keepalive does not necessarily stop the old worker. The owner therefore approved a minimal attempt identifier checked on every native history write and readable projection/status write: a reclaimed attempt fences older workers without a new timer, lease service, middleware or scheduler. All checks and database mutations are atomic; native ConflictDetector also rejects non-continuations.

On redelivery, restore the readable current turn from native messages after its last user message, retaining already authorized private chart references and matching prior tool displays by native call ID. Discard uncommitted streaming fragments rather than duplicate them. Invoke the native Agent with the same conversation ID and no new user message; it continues from the last persisted complete tool round. If that current turn already ends with a native assistant final text response (not a tool-call, reasoning-only or commentary-only message), project completion without another provider request. Initial reference context and all native signatures remain untouched in canonical history.

Disable Send and reject submission only while that conversation has active work. This is not a per-user AI quota or a cross-conversation scheduler. No database write transaction spans provider, MCP, Mercure, broker or initial schema/template I/O.

Selection is explicit in the URL, forms and snapshot requests; it is not mutable global/session per-user selection. Owner-scope every lookup, including favourite, snapshot and charts. Use conversation-specific Turbo transcript and Send-button targets on the existing private account topic. Updates for other selected conversations have no matching DOM target. Terminal snapshots re-enable Send without replacing a typed draft or CSRF token. Successful selected-chat submission returns acknowledgement only, never a captured Pending transcript or Send state. The existing chat controller clears the input only if no input edit occurred after submission and requests an authoritative catch-up through the existing guarded mechanism. Validation, credential and dispatch errors render only the composer error target, preserving the document, native EasyAdmin confirmation handlers, draft and CSRF token.

Publish incomplete token frames as detached view arrays at the existing cadence, after a bounded indexed scalar attempt check; never mutate the managed conversation for ephemeral output. Persist fenced readable projections at lifecycle/tool completion and final boundaries, retaining chart authorization before delivery. Native message save points remain authoritative and recovery intentionally discards incomplete fragments. Restore native Commentary content as well as phase-tagged Text into the readable commentary and completed-text accumulator. This introduces no new checkpoint engine or delivery version subsystem.

Sidebar navigation uses native EasyAdmin Sidebar:Item and ActionMenu, with compact New chat and modal search controls. Favourites precede nonduplicate Chats; both retrieve at most six scalar rows per keyset page, render five, and use independent full-page Show more/Show latest links; one separately retrieved selected entry stays visible. Navigation reads owner-scoped IDs, labels, favourite flags and status only. Sidebar links/forms retain native full-page navigation for EasyAdmin confirmation initialization.

Title text and Delete availability update through targeted native Turbo streams on admission, terminal publication and catch-up, not every token. Preserve row selection, open action menu and CSRF fields; morph only the stable Delete button. The existing catch-up guard tracks explicitly configured current-row targets. No retention indicators or Save streams remain.

Row actions offer reversible Favourite/Remove favourite and confirmed Delete. Delete is owner-scoped and CSRF protected; reject active work in the same short atomic transaction, then remove private conversation charts after commit. Preserve selection when deleting another conversation; deleting the selected one opens an unstored draft. No bulk delete, rename, archive or folders are introduced.

Retained history belongs to the Finance user and remains readable while disconnected and continuable after reconnect with current credentials. Connection epochs protect queued work; they do not partition retained history or permanently make older chats read-only. New conversations capture current model/reasoning defaults; retained conversations keep their captured model/reasoning. ChatGPT remains the sole provider in this slice.

## Alternatives considered

- The demo's session cache or flattened assistant text loses durable ownership/native replay information.
- Moving native JSON to the Doctrine bridge's separate row shape requires a converter or extra table and still needs application metadata, atomic retention and owner enforcement.
- A global mutable selected conversation or fixed transcript target mixes tab selections and asynchronous replies.
- New locks, lease timers, outbox, per-user quotas or a scheduler exceed this slice; native broker redelivery, short writes and attempt metadata cover the approved checkpoint-restart boundary.

## Consequences and limits

The first-slice no-status/no-claim limitation in ADR 0024 is amended by these short durable state transitions and native checkpoint restart. This is not exactly-once inference or restoration of an in-flight provider stream: an unfinished model request or tool round may run again, and fencing cannot undo an external call already in progress. Database state is fenced; Mercure delivery remains best-effort and reload reads authoritative state. Process death after admission but before dispatch can still leave Pending work protected and busy because there is no outbox. A dispatch exception marks a still-Pending matching generation failed; caught generation errors remain terminal failures. Other chats remain available, and New may be refused if all five temporary chats are protected. Legacy broker payloads lack stable generation IDs and are ignored/acknowledged rather than replayed; the owner permits discarding those old chat jobs instead of draining them. No bulk queue purge is authorized; preserve imports and new-format jobs. No migration rewrites existing message payloads or invents execution history for old turns.

No rename/archive/provider selector or context compactor is added. [ADR 0028](0028-native-chat-search.md) amends the original search exclusion with owner-approved native full-text search and recorded canonical demo chats. Generated migrations preserve prior applied history; sidebar/delete needs no schema change. Browser coverage remains one canonical-fixture happy controls journey, adapted to New, menu Save of a populated recorded chat, direct saved link, reload, search and confirmed deletion, plus the existing worker chat journey. The existing replay cassette is stale for current chart tools, so worker/provider proof requires a separately authorized isolated live run. Static/container checks do not establish that proof.

## Owner-approved persistent-chat redesign (2026-11-05)

This decision supersedes the temporary/Save/inline-search portions above: retain every chat automatically, never prune on creation, and replace Save with reversible Favourite/Remove favourite. Existing `saved` database values map to the domain favourite property; no data rewrite or migration is needed. New is a plain compact compose link to an unstored draft; the first admitted message creates the conversation. Existing empty rows remain untouched. Favourites and other Chats form nonduplicate lists with independent bounded keyset pages and selected-entry visibility. Remove retention icons/tooltips and inline search. Search uses native EasyAdmin Modal/Bootstrap dismissal, a small Stimulus shown-event autofocus listener with disconnect cleanup, and an internal Turbo Frame GET for existing owner-scoped FTS results. Result links and sidebar navigation use native full-page navigation to retain EasyAdmin confirmation initialization. Only existing selected composers opt into Turbo streams; draft first-submit uses a native POST redirect. Confirmed inactive-only owner-scoped deletion and native recovery are unchanged. The five English recordings remain lossless: four favourites, one ordinary chat.

The owner also removed the local reset environment opt-in. Dev/test, canonical demo-operator/nonadmin, native loader, confirmation/CSRF and import-busy protections remain. No reset execution is part of this change.
