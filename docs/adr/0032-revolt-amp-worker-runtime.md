# ADR 0032: Cooperative Messenger and Symfony AI execution on Amp/Revolt

- Status: Accepted
- Date: 2026-11-12
- Supersedes: the native worker-pool runtime portion of [ADR 0013](0013-symfony-ai-agent-runtime.md), not its native Symfony AI loop or context-handoff decision.
- Amends: the worker runtime references in [ADR 0029](0029-native-chat-store.md) and [ADR 0031](0031-local-demo-packaging.md); their storage, delivery and packaging decisions remain unchanged.

## Context

The owner explicitly selected one PHP process with cooperative execution on Revolt and Amp instead of Messenger's native `--concurrency` pool. Provider waits should let other handlers progress without replacing Symfony AI's agent loop, history, progress events or toolbox semantics.

A disposable experiment with the installed Symfony AI `FiberToolExecutor` showed that its manual raw-fiber resumption bypasses Amp-managed waits. It is not a compatible scheduler for this runtime. Native asynchronous HTTP interfaces alone also do not establish Revolt cooperation: the actual injected transport must yield to Amp.

## Decision

Use `app:messenger:consume` in development, isolated browser and production Compose workers. Keep the existing transport selection (`scheduler_default` where applicable, `statement_import`, `chat`), five-second lease renewal, 256 MiB memory limit, 3600-second intake limit and noninteractive execution. Remove native `--concurrency` from these worker commands. The ordinary framework `messenger:consume` remains available for framework tooling, not as the configured application worker.

Keep Symfony's native `Worker`, injecting a small `MessageExecutionStrategyInterface` implementation with at most ten Amp futures in flight. Revolt owns the event loop and Amp owns fiber suspension; no manual `Fiber::resume()`, child worker pool, second event-loop runner or custom agent loop is added. Ten is a consumer-local in-flight bound, not a per-user allowance, fairness guarantee, quota or instance-wide admission system.

Each future delegates dispatch to its own native `SyncMessageExecutionStrategy`, retaining Symfony's AckStamp, error and batch dispatch semantics without sharing that strategy's mutable held-ack state across handlers. Its receipt-bound native completion callback is retained and invoked by the worker's draining control flow, not substituted with a generic callback. The acknowledgement bool remains captured by reference. Native acknowledgement queueing is forwarded unchanged; terminal settlement remains with Worker and the transport. No envelope reconstruction or new receipt identity is introduced.

SIGTERM, SIGINT and SIGQUIT stop intake and cancel idle notification waiting; existing in-flight handlers and their native completions drain before exit. Keepalive uses a Revolt timer so lease renewal continues during Amp I/O suspension, including drain. It reuses the native queue transport's busy-operation deferral. Shared services are reset only after all in-flight handlers and their completion callbacks drain, and at final shutdown, never on each interleaved WorkerRunning event. Memory/time stopping does not promise interruption of a synchronous blocking operation or a fixed shutdown deadline.

Use a command-scoped idle hook and the installed sqlite-queue `Transport::waitAny()` on its separate notification connection. Poll scheduler readiness within a bounded one-second idle budget; use a 100 ms budget while handlers are active. At the in-flight limit, await handler completion with bounded scheduler ticks. Configure Worker sleep to zero, avoiding its blocking Clock sleep. Do not copy the reference runtime's wait/session orchestration, sender serialization or recovery machinery.

Inject explicit, untraced Symfony `AmpHttpClient` services for ChatGPT provider/authentication, chart MCP, Jev, Mercure publication and scheduled ECB requests. Preserve existing request/default options; do not globally replace framework HTTP/profiler infrastructure or log private HTTP arguments/bodies. Native test cassette transport decorations remain unchanged. Use the normal Composer-locked dependencies without an upstream fork or vendor overlay.

### Amendment: align Hatfield defaults

On 2026-11-13 the owner approved raising the original four-handler bound to ten to match Hatfield at `3e613dd6e4cd9ddccd3557f42f73f0b18059a74c`: `config/hatfield.defaults.yaml` sets `runtime.llm_concurrency: 10`, `RuntimeConfigDTO::DEFAULT_LLM_CONCURRENCY` is ten, and `LlmFiberConsumeCommand` explicitly passes the runtime setting into its strategy. Its low-level strategy constructor fallback of four is not the effective LLM default. Finance retains its current consumer/transports; Hatfield's separate unlimited tool consumer is not copied.

The HTTP setup already matches: Hatfield's LLM service constructs plain Symfony `AmpHttpClient`, and its provider factory uses `withOptions()` for request options only. Finance's separate private clients likewise omit a pool override. Keep the locked native constructor's `maxHostConnections = 6` and its `ConnectionLimitingPool::byAuthority()` pooling, without a redundant literal override or HTTP refactor. This is a per-authority connection limit in each native client pool, not a global six-request cap or a handler limit. Symfony documents this as client-level configuration, not a per-request option. Preserve finance's existing timeouts/default options, untraced clients and cassette decorations. Source comparison establishes this alignment, not ten-handler load behavior or measured HTTP overlap; no additional concurrency/load scenarios are authorized by this amendment.

### Amendment: temporary application-owned tool executor

Initially, this ADR selected the upstream optional `Symfony\AI\Agent\Toolbox\AmpToolExecutor`, prohibited an application copy and required experimental source linking because the locked release did not supply it. The owner subsequently explicitly authorized a temporary application-owned copy so a clean Composer installation works without a fork or vendor overlay. This supersedes only that no-duplication/source-linking choice, not the other runtime decisions.

Construct `App\Chat\AmpToolExecutor` with the same owner-bound native decorated toolbox supplied to Agent. Copy the upstream algorithm from published commit [`57961ae9`](https://github.com/ineersa/ai/blob/57961ae9/src/agent/src/Toolbox/AmpToolExecutor.php), retaining MIT attribution and source provenance. Yield progress in input order before starting Amp futures, settle every started sibling with `awaitAll()` before propagating the first observed error, and return results in input order. Exclude this manually constructed executor from automatic service discovery; do not introduce a globally bound toolbox. Amp is already a direct production dependency, so no optional-dependency checks or fallback paths are needed.

Once an appropriate Symfony AI release contains the executor, update the locked dependency, replace the factory's application executor with the released class and remove the temporary copy and its DI exclusion. The upstream contribution is [Symfony AI PR #2938](https://github.com/symfony/ai/pull/2938) and proceeds independently. Do not rewrite `FiberToolExecutor` or create a custom agent loop: Symfony AI continues to own the model/tool loop, native tool semantics, progress and message store.

### Amendment: shared-runtime integration boundaries

On 2026-11-13 the owner approved correcting three concrete integration boundaries in the pinned dependencies without changing the native Worker/strategy architecture or general Amp tool executor:

- **OAuth file locking:** the pinned ChatGPT `AuthFileStore` acquires a native Symfony lock in blocking mode and holds it through the update callback, including OAuth refresh HTTP. If that HTTP wait yields to Amp, a second handler's blocking `flock()` prevents the first from resuming and releasing its lock. This is a concrete deadlock path, not an unproven generic hazard; FlockStore's locks do not expire after the requested TTL. Keep native `AuthFileStore`, `LockFactory`, lock keys, full-update exclusion and atomic writes. Supply a narrow `CooperativeFlockStore` whose exclusive blocking-acquisition extension point retries native nonblocking `save()` with `Amp\delay()` on contention. Store its lock files in `locks/` below the selected auth directory, shared between web and worker by the development bind mount, isolated-browser private mount or production private volume. Do not rely on container-private `/tmp`, release the lock during refresh, inspect/migrate grants or serialize whole conversations. The synthetic replay auth directory retains its separate lock namespace.
- **Doctrine clearing:** omitting `ResetServicesListener` is insufficient: DoctrineBundle globally registers `DoctrineClearEntityManagerWorkerSubscriber` for both handled and failed messages. Temporarily detach only that native subscriber from the command's dispatcher while this cooperative consumer runs; its scoped dispatcher continues to deliver all other events/listeners. Invoke the native subscriber's all-manager clearing together with service reset only after every in-flight handler and completion callback drains, including final shutdown. Restore the subscriber in `finally`, preserving ordinary stock-consumer behavior. Do not replace native clearing or introduce generic event routing.
- **MCP requests:** the pinned SDK HTTP transport stores one active request fiber, suspension and SSE stream; it is not reentrant. Wrap each agent's native `ClientToolset` in a small `SynchronizedMcpToolset` using the installed Amp `LocalMutex`. Hold that per-client mutex through native discovery (including lazy connect/initialization and pagination) or a native tool call, releasing in `finally`. Connection-loss handling remains inside the protected native operation. Different clients/conversations and non-MCP sibling tools remain independent; native schemas, errors and private chart retention are unchanged. Declare `amphp/sync` directly when using its already-locked mutex API.

## Alternatives considered

- Keep native Messenger `--concurrency=4`: explicitly replaced by the owner for this cooperative experiment.
- Use the installed `FiberToolExecutor` unchanged: rejected by the measured Amp suspension incompatibility.
- Broadly reimplement AckStamp/batch dispatch, tool semantics or the agent loop in the application: unnecessary when native extension points suffice. The explicitly authorized temporary executor copy only supplies the unpublished Amp scheduling algorithm.
- Import the reference runtime's complete consumer/wait/session machinery: unnecessary for the selected fixed transports and native queue wait support.

## Consequences and remaining verification

The runtime shares services in one PHP process. Current handlers bind trusted owners explicitly: tenant SQL uses an owner-bound tool clone, imports open/release a handler-local tenant manager, and native chat history/metadata use short per-operation DBAL work. The central ORM and its identity map remain shared. Deferring both native Doctrine clearing and service resets to drained boundaries avoids per-message detachment of suspended peers, but source inspection is not proof of every shared-service interaction.

Synchronous SQL, file/CPU work and callbacks can still stall Revolt. The browser stack excludes Scheduler/ECB, so ordinary replay journeys do not establish live scheduled-rate HTTP cooperation. Auth contention now yields without releasing native cross-process exclusion, and MCP requests cooperate while waiting for their own client's mutex. The queue client allows one operation per connection; preserve its native keepalive deferral and separate notification connection rather than add speculative serialization.

No quotas, conversation/per-user admission locks, transport retries, recovery engine, generation fencing, transaction held over model I/O, alternate transcript or data migration is added. Native at-least-once delivery and optimistic history conflicts keep their existing limitations. The earlier authorized live pair established bounded same-process chat overlap, not contended OAuth refresh, overlapping sibling MCP calls, the described ORM completion ordering, lease safety, graceful shutdown or cross-user isolation. These corrections follow the pinned sources; main must run the existing relevant browser happy paths and static gate. New concurrency, contention, fault or security scenarios require separate explicit owner permission and are not introduced or run by this amendment.
